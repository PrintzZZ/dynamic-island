# 时间应用 · 二级导航「卡片堆栈」设计方案

> 用横向 Card Stack / Carousel 取代时间应用顶部的分段控件（`.seg`）。
> 本文是**设计规格**，不含代码改动。所有数值都基于对现有布局的实测推导。

---

## 0. 设计目标与硬约束对照

| 约束 | 方案如何满足 |
|---|---|
| 不像传统 Tab | 没有等宽按钮条、没有下划线滑块、没有选中底色块 |
| 不是一排小按钮 | 导航载体是"卡片本身"，模式名只出现在身份行一处 |
| 没有圆点分页器 | 位置感完全由"左右露出的卡片边缘"提供 |
| 没有可见箭头按钮 | 换页 = 拖拽 / 点击露出的邻卡边缘 / 键盘方向键 |
| 邻卡只露 8–18px | 定稿 **12px**（几何硬值，见 §2） |
| 邻卡不显示大量文字 | 12px 露出下**一个字都看不到**，只有卡边 |
| 当前卡显示该模式最关键信息 | 当前卡直接渲染该模式的**真实面板**（大号时间 / 25:00 / 下一提醒 / 18:42） |
| 不是后台系统风格 / Material | 无 elevation 阴影层叠、无波纹、无 4dp 网格、无彩色大圆角块 |
| 不出现"卡片里套卡片" | 当前卡用**极淡中性表面**（不是彩色大卡），内部已有的分组块是"表面上的控件"，层级正确 |
| 一屏不放四个模式 | 一屏只完整呈现 1 张卡，另两侧各露 12px |
| 不影响现有功能 | 四个面板、`WorkPanel`、岛容器、设置窗口、主进程**全部不改** |

## 1. 展开态完整布局

### 1.1 垂直预算（实测推导）

```
.pill                     384 × 480
├─ .header（岛头部，现有）        48px   拖动把手 + 应用标签 + 固定 + 关闭
├─ 1px 发丝线                   1px   .body 的 border-top
└─ .body                        431px
   └─ .time-app  height:100%    431px  padding: 0 0 11px
      └─ 内容区                  420px
         ├─ .mode-bar 身份行     30px   【新增】
         ├─ 间距                  8px   【新增】
         └─ .deck 轨道视口       382px  【新增，取代 .seg】
```

**对照今天**：`.seg` = 按钮 24.6px（`padding:6px 2px` + 内容行高 12.6px）+ 容器 padding 6px + `margin-bottom: 9px` ≈ **39.6px**，面板实得 ≈ **380.4px**。

**结论**：新方案 382px，比今天**多 1.6px**。垂直方向**零回流**。

### 1.3 身份行 `.mode-bar` 结构

```
┌───────────────────────────────────────────────────────────────┐ 30px
│ ⠿        ●        时间                              ⋯         │
│ 22×22    6⌀       13px/600                       28×28        │
│ 拖动     状态      当前模式名                      更多         │
│ ↑padding-left 6        ↑gap 7      ← 弹性空白 →   padding-right 14│
└───────────────────────────────────────────────────────────────┘
```

| 槽位 | 规格 | 说明 |
|---|---|---|
| 拖动区域 | 22×22 命中区，图标 13px `⠿` | 见 §1.4 的重要说明 |
| 状态圆点 | 6px ⌀，`background: var(--mode-accent)` | **反映运行态而不只是身份**，见下表 |
| 当前模式名 | 13px / 600 | 时间 / 计时 / 提醒 / 专注 |
| 弹性空白 | `flex: 1` | — |
| 更多 | 28×28，图标 15px | 点击弹小菜单，见 §1.5 |

**状态圆点的语义**（这是它比单纯色点更有价值的地方）：

| 模式 | 状态 | 圆点表现 |
|---|---|---|
| 时间 | 常态 | `accent` @ 100% |
| 计时 | 运行中 / 暂停 | `accent` + 1.6s 呼吸脉冲 / `accent` @ 35% |
| 提醒 | 有未完成提醒 / 无 | `accent` @ 100% / `accent` @ 25% |
| 专注 | 专注中 / 空闲 | `accent` + 1.6s 呼吸脉冲 / `accent` @ 25% |

> 圆点颜色随模式切换用 `transition: background 0.28s ease` 过渡到新 `accent`，**不做位移动画**（不要让它跟着卡片滑动，那是"指示器"的路子，会变成 Tab 滑块）。

### 1.4 关于"拖动区域"的重要说明

岛头部（48px）**已经有**一个可拖动把手，且 `onPillDown` 在展开态对窗口拖动是 no-op，展开态的面板拖动靠 `.header` 的把手。

身份行再放一个把手，功能上是**冗余**的。这里给两个选项：

- **方案 A（推荐）**：保留这个把手**仅作为视觉配重**（左对齐的 `⠿` 图标，`opacity: 0.28`，`cursor: default`，**不绑任何事件**）。作用是让身份行左侧不空，与岛头部把手的视觉语言连贯。
- **方案 B**：不做把手，把「状态圆点 + 模式名」整体左移到 `padding-left: 14px`。

如果希望身份行**也能拖动窗口**，必须走现有的手动 `mousedown → IPC setPosition` 路径，**绝对不要**用 `-webkit-app-region: drag`（无边框窗口下会闪烁，这是本项目已踩过的坑）。

### 1.5 「更多」菜单内容

三个真实动作，全部复用已有能力，不新增 IPC：

| 菜单项 | 行为 |
|---|---|
| 打开时间设置 | 打开设置窗口并定位到「应用 → 时间」 |
| 重置当前模式 | 只清空当前模式的运行态（计时归零 / 提醒列表不动 / 专注结束），不触碰其它模式 |
| 隐藏此模式 | `update({ enabledSubs: { ...enabledSubs, [id]: false } })`，卡片向右滑出、轨道重排 |

> 「隐藏此模式」让 `visibleModes` 收缩这条路径变成**用户日常会触发的正常流程**，而不是只在设置窗口里才会发生 —— §9.4 的处理就变得必要而非理论。

### 1.6 子页（工作时间）

`view === 'work'` 时，**身份行与轨道整体隐藏**，`WorkPanel` 占满 420px（保持现状）。`WorkPanel` 自带返回入口，不需要卡片堆栈参与。

## 2. Card 尺寸建议

### 2.1 定稿几何

| 项 | 值 | 推导 |
|---|---|---|
| 轨道视口 `.deck` | **384 × 382** | 满宽（`.time-app` 水平 padding 归零），被 `.pill` 的 `overflow:hidden` 裁切 |
| 卡片间距 `gap` | **8px** | — |
| 单侧露出 `S` | **12px** | 落在 8–18px 要求内 |
| 卡片宽 `W` | **344px** | `384 − 2×8 − 2×12 = 344` |
| 卡片高 `H` | **382px** | 占满轨道视口高度 |
| 卡片内边距 | `6px 10px 4px` | 垂直 6/4 避免内容贴卡边，水平 10 |
| 面板槽 | **324 × 372** | `344−20` × `382−10` |
| 卡片圆角 | **22px** | 胶囊 34px，差 12px，嵌套层级读起来正确 |
| 步长 `step` | **352px** | `344 + 8` |
| 轨道定位 | `x(i) = 20 − 352·i` | `20 = (384−344)/2` |

**几何自校验**：
- 当前卡 `i`：左边缘在轨道坐标 `352i`，位移 `20−352i` → 视口坐标 **20**，右边缘 364 ✓
- 左邻卡：右边缘在视口坐标 `20−8 = 12` → 露出 **12px** ✓
- 右邻卡：左边缘在视口坐标 `364+8 = 372` → 露出 `384−372 = ` **12px** ✓

### 2.2 为什么必须"满宽 + 贴边"

若沿用 `.time-app` 现有的 `padding: 0 13px`，视口只有 358px，则 `W = 358−40 = 318`，面板槽只剩 294px（比今天窄 64px），`ClockPanel` 的 60px 大数字会危险。**把水平 padding 归零、让卡片贴到胶囊内缘，是保住面板宽度的唯一办法**，而且视觉上更好（卡片像是从胶囊里滑出来的）。

### 2.3 宽度影响与已验证的余量

面板槽 **324 × 372**，对照今天 **358 × 380.4** → **宽 −34px（−9.5%）、高 −8.4px（−2.2%）**。

已逐个核对最宽/最高的敏感点：

| 面板 | 敏感处 | 固定占用 | 324 下实得 | 判断 |
|---|---|---|---|---|
| ClockPanel | `.big-time` 60px，`timeText` = `HH:MM`（实测 5 字符 ≈ 149px）；`.now-row` 固定 8(padding)+12(gap)+100(mini-face) = 120 | 120 | `.now-text` = **204px**，余 **55px** | ✅ 不溢出 |
| ReminderPanel | 时间列 56 + 开关 32 + 删除 20 + 3 段 gap ≈ 30 + 行内 padding ≈ 24 | ≈162 | 信息列 ≈ **162px**，`.lb` 有 ellipsis | ✅ |
| CountdownPanel | 圆环 180px 居中 | 180 | 324 | ✅ |
| FocusPanel | 圆环 180px 居中 | 180 | 324 | ✅ |
| ClockPanel / FocusPanel | 均 `overflow-y: auto`，高度不足时可滚 | — | 372 | ✅ |

### 2.4 若要求"宽度零回流"

把卡片水平内边距降到 4px（`padding: 6px 4px 4px`）→ 面板槽 **336 × 372**，宽度只差 −22px。代价是卡片内容离圆角边界偏近（22px 圆角 + 4px 内边距，只有顶部/底部两行会贴到弧线上）。**默认不采用**，作为备选。

> 注意：**恒定为 344 宽居中**，即使只启用 1 个模式也不改成满宽 —— 让用户在设置里开关子模式时，面板宽度保持恒定，不产生"改设置导致布局跳变"。

## 4. 字号层级

**核心原则：卡片内部不新增任何字号，四个面板现有的字号层级原样保留。**

| 层级 | 元素 | 字号 | 字重 | 颜色 | 说明 |
|---|---|---|---|---|---|
| L1 | 岛头部应用标签 | 现有 | 现有 | 现有 | 不动 |
| **L2** | **卡片主信息** | 面板自定（60px / 圆环 22px / 15px） | — | — | **最高视觉权重，当前卡 100%** |
| L3 | 卡片次级信息 | 面板自定（11px 为主） | 500 | `rgba(255,255,255,0.40)` | 不动 |
| **L4** | **身份行·模式名** | **13px** | **600** | 当前 `rgba(255,255,255,0.92)` / 切换中 `0.55` | 唯一新增字号 |
| L5 | 更多按钮图标 | 15px | — | `rgba(255,255,255,0.42)`，hover 0.72 | — |
| L6 | 拖动把手图标 | 13px | — | `rgba(255,255,255,0.28)` | — |

**刻意不做的事**：
- ❌ 卡片内**不重复模式名**。身份行已经是唯一的模式标识（13px），卡片里再放一个"倒计时"标题就是冗余，还会吃掉 20px 垂直空间。
- ❌ 邻卡**不显示任何文字**。12px 露出本来就看不到，不要为了"露出时有内容"而缩小字号。
- ❌ 不加"1 / 4"这类计数。
- ❌ 模式名只有 13px 一级，**不做 active/inactive 两级字号**（那会变成 Tab）。

**层级排序**（从高到低）：卡片主信息 → 身份行模式名 13px → 面板次级信息 11px → 辅助 10.5px。身份行落在"卡片主信息之下、面板次级信息之上"，正好是"模式级标签"应有的位置。

## 5. Card 前后层级关系

### 5.1 角色划分（按连续距离 `d = |i − p|`，`p` 为轨道当前"浮点索引"）

| 角色 | 条件 | 视觉 |
|---|---|---|
| **当前卡** | `d = 0` | `scale 1.00`，`opacity 1.00`，`blur 0`，无遮罩，**全彩全字号** |
| **相邻卡** | `d = 1` | `scale 0.94`，`opacity 0.62`，`blur 0.6px`，遮罩 `rgba(0,0,0,0.30)` |
| **远端卡** | `d ≥ 2` | `scale 0.90`，`opacity 0.30`，`blur 1.4px`，遮罩 `rgba(0,0,0,0.45)` |

关键：`d` 是**连续值**（由轨道实时 `x` 反算），不是离散的"是/否当前"。这正是 Apple 卡片堆栈的核心 —— 拖到 30% 时，两张卡是"半当前"，不会在 50% 处突然跳变。

### 5.2 内容深度策略

- **当前卡 = 该模式的真实面板**（`ClockPanel` / `CountdownPanel` / `ReminderPanel` / `FocusPanel`）
- **相邻卡 = 同一套面板**（不是封面），因为拖拽到一半时它会被露出大半，封面会露馅
  挂载策略见 §10

### 5.3 遮挡与裁切

- 邻卡**不做 "被当前卡压住" 的负 margin 叠压**。它们是**横向并排 + 缩小**，间距 8px。这样：
  - 拖拽时邻卡是"滑进来"而不是"从底下钻出来"，与 `translateX` 的物理感一致
  - 不会出现邻卡的圆角与当前卡圆角重叠打架
- 胶囊 `.pill { overflow: hidden; border-radius: 34px }` 负责最外层裁切。卡片底部会轻微进入胶囊圆角弧线区（y > 446），这是**期望效果**（卡片"收进"胶囊角落）。

### 5.4 z 轴

`z-index` 固定为 `10 − d`（当前 10，邻卡 9，远端 8）。因为卡片不重叠，`z-index` 实际只用于保证遮罩层顺序正确。

## 6. 拖拽过程中的视觉状态

### 6.1 状态机

```
idle ──pointerdown──▶ pending ──|dx|>8 且 |dx|>|dy|──▶ dragging ──pointerup──▶ settling ──▶ idle
                          │                                   ▲
                          └──|dy|>8（纵向）──▶ idle（交给面板滚动）
```

| 状态 | 进入条件 | 行为 |
|---|---|---|
| `idle` | 静止 | 轨道停在整数索引；卡片基础 transform |
| `pending` | `pointerdown` | **不做任何视觉变化**。只记录 `startX/startY/t`。作用：把"横向换卡"和"纵向滚面板"分开 |
| `dragging` | `|dx| > 8 && |dx| > |dy|` | 见 §6.2 |
| `settling` | `pointerup` / `pointercancel` | 见 §6.3 |

**轴锁阈值 8px**，一旦锁定方向就不再改判，避免拖到一半窜轴。

### 6.2 `dragging` 的视觉状态（逐项）

| 对象 | 变化 |
|---|---|
| **轨道** | `transform: translate3d(x, 0, 0)`，**跟手、无缓动、无 transition** |
| **`.deck`** | 加 `.is-dragging` 类：`cursor: grabbing`；所有卡片 `transition: none`（跟手期间不能有补间拖尾） |
| **当前卡** | `scale 1 → 0.985`，`opacity 1 → 0.94`（"被按下"的轻微退让） |
| **拖拽方向的邻卡** | 随位移连续升到 `scale 0.985`、`opacity 0.94` —— 两张卡在视觉上**交接**，交班瞬间没有主次断层 |
| **反向的第三张卡** | `scale → 0.90`、`opacity → 0.30` |
| **邻卡 blur** | `0.6px → 0.2px`（正在"变清晰"） |
| **指针按下的那张卡** | `filter: brightness(1.04)` —— 极弱高光，作为 `pending → dragging` 的确认反馈 |
| **端点橡皮筋** | `i = 0` 且 `dx > 0`（或末端反向）时：`visualX = dx * 0.35`，上限 `60px`。松手必定回弹 |
| **身份行** | `|dx| > step × 0.5` 时，模式名与状态圆点**交叉过渡**：旧名 `opacity → 0`（0.18s）→ 新名 `opacity 0 → 1`（0.22s，延迟 0.06s）；圆点 `background` 0.28s 过渡到新 `accent` |
| **底部操作按钮** | **不做任何固定/浮动**。它们属于面板，跟着卡片一起水平移动（这正是"卡片"该有的行为） |

> 身份行的交叉过渡很关键：它让"当前是哪个模式"这个信息在**拖到一半时就更新**，而不是等落位才跳。这是把这个设计从"滑块"拉向"卡片堆栈"的细节。

### 6.3 `settling` 的判定与动画

**落点判定**：

```
v = 最近 100ms 的位移速率 (px/ms)
翻页  ⟸  |dx| > step × 0.28 (≈98px)  ||  |v| > 0.45
回弹  ⟸  其它情况，以及任何越界情况
```

**动画**（两种落点用同一套 tween 结构，只换 ease 和时长）：

| 落点 | duration | ease |
|---|---|---|
| 翻页 | `clamp(0.34 + 剩余距离/step × 0.14, 0.34, 0.52) × motionScale()` | `power3.out` |
| 回弹 | `0.30 × motionScale()` | `power2.out` |

- `motionScale()` 为 0（关动画）时用 `gsap.set` 直接就位，不做补间
- `overwrite: 'auto'` 防止快速连续拖拽时 tween 堆叠
- **卡片的 scale / opacity / blur 全部在同一个 tween 的 `onUpdate` 里由轨道实时 `x` 反算**，绝不另开一条 tween。两条 tween 并行必然产生脱节（这是最容易翻车的地方）
- 落位后写回 `setMode(visibleModes[target].id)`（或直接更新 `state.mode`），`activeIndex` 由 `watch` 同步

### 6.4 点击抑制

`dragging` 期间累计位移 > 6px → settle 后 **80ms 内吞掉一次 `click`**（复用项目已有的 `suppressClick` 模式）。否则松手时会误触卡片内部的按钮（`CountdownPanel` 的开始/重置、`ReminderPanel` 的开关）。

### 6.5 与窗口拖动的关系

- 在 `.deck` 上 `pointerdown` 必须 `e.stopPropagation()`。经核实 `onPillDown` 在展开态已是 no-op，但**仍要 stop**，避免将来 `onPillDown` 逻辑变动后拖卡片带动整个窗口。
- `touch-action: pan-y` —— 纵向交给浏览器（面板滚动），横向由 JS 接管。

## 7. Card 切换动画表现

四种入口必须**统一手感**，否则会出现"点一下跳一下、拖一下另一种感觉"的廉价感。

| # | 入口 | 动画 |
|---|---|---|
| 1 | **拖拽翻页** | §6.3：`power3.out`，0.34–0.52s，起点是"跟手位置" |
| 2 | **点击邻卡露出的 12px** | 同一次翻页，起点是静止整数位 → `duration 0.42s`，`power3.out`。`.deck` 上 `cursor: pointer` 只在邻卡区域生效 |
| 3 | **外部跳转**（`ClockPanel` 的 `@open-reminder` → `setMode('reminder')`，或「更多」→ 重置） | **跨 1 张**：同 (2)。**跨 ≥2 张**：**先"抽卡"再"插入"** —— 旧卡 `scale → 0.92 / opacity → 0`（0.16s，`power2.in`）→ 轨道 `gsap.set` 瞬移 → 新卡 `scale 0.92 → 1 / opacity 0 → 1`（0.30s，`back.out(1.05)`）。**禁止长距离横滑**：384px 宽的容器里滑 2 张卡要 1s 以上，非常拖沓 |
| 4 | **设置里开关子模式导致 `visibleModes` 变化** | 当前模式仍存在 → 轨道滑到新索引（0.34s）；当前模式被移除 → 被移除卡 `opacity → 0 / scale → 0.9`（0.22s）后再重排轨道；可用模式变为 1 → 轨道 `x` 归位到 20，所有卡片 `scale/opacity` 回到 1 |

**入场/出场不额外做动画**：
- 岛展开时 `revealExpanded()` 已经把 `.body` 从 `y:22 / scale:0.97` 拉起，卡片堆栈**不再单独入场**，身份行随 `.body` 一起进来即可（叠加会显得乱）
- 切到时间应用时 `<Transition name="app">` 已有动画，同理不叠加
- **删除现有的 `.panel-enter/leave-*` 过渡**：卡片切换已经承担了模式切换的全部动效，再留一个面板淡出淡入就是双重动画

**禁止的动画**：
- ❌ `scroll-behavior: smooth` + `scroll-snap`（与面板 `overflow-y:auto` 及滚轮语义冲突）
- ❌ 弹性 `back.out` 幅度过大（> 1.2）会让卡片看起来"甩出去"，与 Apple 的克制不符
- ❌ 卡片切换时同时做纵向位移动画（面板内容会看起来在抖）

## 8. opacity / scale / blur 建议

### 8.1 静止态

| 位置 | scale | opacity | blur | 遮罩 |
|---|---|---|---|---|
| 当前卡 | **1.000** | **1.00** | **0** | 无 |
| 相邻卡 | **0.940** | **0.62** | **0.6px** | `rgba(0,0,0,0.30)` |
| 远端卡 | **0.900** | **0.30** | **1.4px** | `rgba(0,0,0,0.45)` |

### 8.2 拖拽中（连续插值）

令 `t = clamp(d, 0, 1)`：

```
scale   = 1 − 0.060 · t
opacity = 1 − 0.380 · t
blur    = 0.600 · t   (px)
scrim   = 0.300 · t   (rgba(0,0,0,·))
```

另外对"拖拽方向上的那一张"叠加 `+0.015` 的 scale 抬升，使两张卡在交接瞬间都接近 0.985/0.94，主次平滑换位。

### 8.3 关键工程建议

1. **静止时 blur = 0**。12px 的露出下 blur 完全不可见，白付 GPU 代价。
2. **blur 只在拖拽过程中启用，且上限 0.6px**。`filter: blur()` 作用在 344×382 的大卡上会触发整层重新栅格化，逐帧动画 blur 是这四张卡上最贵的操作。远端卡**用纯 opacity 降级，不用 blur**。
3. **首选 Phase 1 直接关掉 blur**，只保留 `opacity + scale + scrim`。0.6px 的差值肉眼几乎不可辨，但省下的合成开销是实打实的。本文保留数值供需要时启用。
4. **`will-change` 只在 `.is-dragging` 期间加**（`will-change: transform, opacity`），落位后移除。常驻 `will-change` 会在四个大卡上长期占用合成层，是明确的内存浪费。
5. **加 `backface-visibility: hidden` + `transform: translateZ(0)`** 到卡片上，避免 0.94 缩放下的文字亚像素抖动。
6. **`transform-origin: center`**。不要用 `left center`，否则缩放会把卡片推向一侧，破坏"露出宽度恒定"的几何。
7. 缩放**不影响布局**（transform 不触发重排），所以 0.94 的邻卡**不会让面板内部重新排版** —— 这是选 transform 而非 width 的根本原因。

### 8.4 浅色主题差异

浅色主题下，深色遮罩会把邻卡"压脏"。建议：

| 项 | 深色 | 浅色（`html[data-theme='light']`） |
|---|---|---|
| 邻卡 opacity | 0.62 | **0.80** |
| 遮罩 | `rgba(0,0,0,0.30)` | `rgba(0,0,0,0.06)` |
| 卡片表面 | `rgba(255,255,255,0.026)` | `rgba(0,0,0,0.022)` |
| 卡片发丝线 | `rgba(255,255,255,0.055)` | `rgba(0,0,0,0.055)` |

> 深色表面靠"提亮"表达层级，浅色表面靠"压暗"，遮罩强度差 5 倍是正常的。

### 8.5 卡片表面（当前卡该不该有背景）

**结论：有，但必须是极淡的中性表面，不是彩色大卡。**

- `background: rgba(255,255,255,0.026)`
- `border: 1px solid rgba(255,255,255,0.055)`
- `border-radius: 22px`
- 顶部一条极细内高光：`box-shadow: inset 0 1px 0 rgba(255,255,255,0.035)`（Apple 的"玻璃上沿"）
- **无外阴影**（`box-shadow` 不做 elevation，这是 Material 的语言）

为什么不是"无背景"：卡片需要一条可读的边缘，否则拖到一半时"内容在飘"而不是"卡在动"。
为什么不是彩色大卡：会与 `ReminderPanel` 内部已有的分组块形成"卡片里套卡片"（明确禁止项）。中性极淡表面 + 内部小尺寸分组块 = iOS 分组列表的正确层级。

## 9. 交互补全

### 9.1 滚轮

| 输入 | 行为 |
|---|---|
| `deltaX`（触控板横滑） | 切卡。**120ms 节流**，单次滚动最多翻一页 |
| `deltaY`（鼠标滚轮 / 触控板纵滑） | **完全不参与切卡**，交给面板自行滚动 |

> 这是对"鼠标滚轮只有 `deltaY`"这个现实的正视：不想用 `deltaY` 切卡，因为会和"滚动提醒列表"打架，误触代价很高。**鼠标用户走"拖拽 + 点邻卡"，触控板用户走"横滑"。** 三条路径都不需要箭头按钮。

### 9.2 键盘

- `ArrowLeft` / `ArrowRight` → 翻页
- **焦点在 `input` / `textarea` / `select` / `[contenteditable]` 内时全部忽略**（`CountdownPanel` 有自定义时长输入框，`ReminderPanel` 有文本输入，这条必须做）
- 在 `.deck` 上 `tabindex="0"`，仅当 `document.activeElement` 位于 deck 内时响应

### 9.3 单模式（`visibleModes.length === 1`）

- 卡片保持 344 宽**居中**（`x = 20`），**不改满宽**（避免设置变更导致布局跳变）
- 禁用：拖拽、滚轮、键盘、邻卡点击
- 身份行保留（仍有模式名与「更多」）
- 没有邻居边缘 → 视觉上就是一张居中的卡，不会误导用户"还能滑"

### 9.4 `visibleModes` 在挂载期间收缩

- 由 `useModeApp` 现有的 `watch(JSON.stringify(appSettings.enabledSubs))` 驱动，`visibleModes` 已是响应式 `ref`
- 若当前 `state.mode` 被移除，`useTimeApp` 已会把它移到第一个可用模式 → deck 通过 `watch(activeIndex)` **只做动画**，不做业务决策
- 卡片数量变化时，轨道长度重算 + `gsap.to` 到新的 `x(activeIndex)`
- 数量降到 1 时执行 §9.3

### 9.5 测量陷阱（必须遵守）

`revealExpanded()` 会在 `.body` 上设置 `transform: scale(0.97 → 1)`，而 **`getBoundingClientRect()` 包含祖先 transform**，会导致按视口测出的宽度小于真实值，轨道定位全错。

**必须用 `clientWidth` / `offsetWidth` 测量**，或使用 `ResizeObserver` 观察 `.deck`。绝对不要在卡片或轨道上用 `getBoundingClientRect()` 做几何计算。

## 10. 内容挂载策略

**推荐：4 个面板全部常驻挂载。**

已验证的前提（这是这个方案能成立的基础）：

- 四个面板**没有任何 `onMounted` / `onUnmounted` / `setInterval` / `addEventListener`**
- `CountdownPanel` 只有 1 个 `watch`（同步自定义时长输入框），无定时器
- 250ms 心跳是 `useTimeApp.js` 的**模块级**单例，与面板是否挂载无关
- 四个面板共享同一契约：根元素 `flex:1; min-height:0; display:flex; flex-direction:column`

收益：**拖拽中露出的邻卡就是真实面板**，不存在"封面 ↔ 面板"的内容跳变 —— 这是卡片堆栈手感的关键，也是唯一能真正做对的方式。代价：4 份 DOM + 4 份响应式订阅（心跳下 `ClockPanel` 每秒重渲染 4 次 → 4 份而非 1 份，单次渲染很小，可忽略）；若计时与专注同时在跑，会有 2 个圆环在动画（可接受）。

**保守降级**（若想最小化改动）：只挂载 `activeIndex` 与"当前拖拽方向上的目标卡"（最多 2 个），其余用轻量占位。但这会在拖过 50% 的瞬间发生内容替换，效果明显打折。
